# Magazine Studio UI/UX 검증 (2026-09-30)

## 검증 범위
- 기준: 71a58a2, 개발 브랜치 codex/magazine-studio-1.1. 실제 Adobe InDesign은 이 환경에서 조작하지 않음.
- 수정 전/후 실제 preview.html + studio-ui.js를 브라우저에서 실행하고 키보드로 버튼 조작.
- tests/serve-ux.cjs를 `node tests/serve-ux.cjs`로 실행한 뒤 http://127.0.0.1:8766/ux-test.html 사용. 노란 배너는 **모의 Host**임을 표시한다. 실제 문서/파일/API 요청 없음. localhost에서 허용된 소스만 제공하며 사용자 INDD와 .git은 제공하지 않음.
- 730개 모의 Style, 검색, Family 펼침, Style 선택, 제목/본문 적용, 캐시 재사용을 검증. 실제 설치 폰트 검증 아님.

## 직접 발견하고 수정한 문제
- 선택 카드에 텍스트 표시가 없고 제작 영역에서 선택한 디자인을 재확인할 수 없었음 → 선택됨 표시, 이름/지면 크기 요약.
- 처리 중 버튼 문구가 그대로이고 내부 API 단계가 사용자 화면에 노출됨 → 버튼 처리 중, 제작 결과를 가까이 표시, 로그는 접힌 상세 진단.
- 폰트 Style 목록이 모두 펼쳐져 있었음 → Family 30개씩, 한 Family만 펼침, 검색, 선택 Style 및 본문/제목 적용됨 표시. 기존 Host 캐시 유지.
- Story 번호만 표시 → Story.textContainers의 AUTO_/JSON_ Label로 역할 식별. 알 수 없으면 텍스트 영역으로 남김. 오류 건수와 수정 안내, PDF 차단 이유 표시.
- 다른 시안을 고르면 이전 검사 결과가 남음 → 현재 문서 키가 일치할 때만 결과 표시. 실패 시 이전 성공 보고서 제거.
- 430px 화면에서 버튼/Preview 가로 넘침 → 버튼 border-box, Preview 여유 폭 보정. mm/pt/원본 프레임은 변경하지 않음.

## Story 323 / 348 / 401
번호는 문서마다 달라지므로 현재 제공 정보만으로 역할을 특정할 수 없음. 모의 화면은 UX 시연을 위해 이 번호를 명시적으로 MOCK으로만 표시하며 실제 문서 분석 결과가 아니다.
새 검사에서는 생성 프레임 Label을 읽어 제목/부제/본문/헤더/푸터/페이지 번호로 안내한다. Adobe 공식 Story DOM의 textContainers / overflows 사용: https://developer.adobe.com/indesign/uxp/dom/api/s/story/

JSON 원본에 작은 텍스트 프레임이 있음: 16pt 부제의 높이 약 4.013mm(11.38pt), 10pt 페이지 번호 높이 약 2.498mm(7.08pt). 제목은 51pt/60pt 행간과 약 34.031mm(96.47pt) 높이이므로 여러 줄일 때 위험. 이것은 실기 확인할 위험 요인이지 특정 Story의 원인 확정이 아니다. 기준선은 ASCENT_OFFSET이며 원본 JSON에 기준선 정보가 없다. 임의 확대/폰트 축소/검사 우회는 하지 않았다.
본문은 연결된 하나의 Story이고 실제 overset이면 후속 페이지를 최대 40페이지까지 생성하는 기존 정책을 유지한다. 제목/부제/페이지 번호는 이 본문 연결 대상이 아니다.

## Preview ↔ InDesign
공통 normalized plan의 page size, 좌표/크기, 단수/단간격, 폰트/크기/행간/자간, 본문 문단간격, inset, 장식선/번호는 기존 테스트 유지. 이번에는 원본 JSON과 Host 생성 치수 변경 없음.
정확한 시각 동일성은 미확인: 브라우저는 본문을 추정 분량으로 나눔, InDesign은 폰트 metric과 실제 조판으로 나눔. CSS 폰트 매칭/weight, 기준선, CMYK 화면색도 다를 수 있음. body 이외 문단간격 확장은 기존 schema에서 금지되어 있어 무시되는 지원 필드로 오인하지 않음.

## 작업 중 정책
문서를 만드는 동안 원고·시안 변경/중복 제작은 잠가 대상 문서 일관성을 유지한다. 설정·AI 설명·상세 진단의 펼침은 허용한다. PDF 안전 검사를 유지하고 실제 export 직전에도 검사한다.

## PC Smoke Test (5~10분)
1. UDT Reload → 예시/무료 시안 버튼이 동작하고 상세 진단은 접혀 있음.
2. 무료 또는 Layout 02 선택 → 카드의 선택됨과 제작 영역의 이름이 같음.
3. 설정 → 폰트 더보기 → 검색 → Family 펼침 → 실제 Style 선택 → 본문/제목 적용 → 현재 폰트 및 적용됨 표시.
4. 새 문서 생성 → 처리 중 즉시 표시, 완료 또는 실패와 상세 진단 확인 가능.
5. 검사 → 역할별 오류와 PDF 차단 사유 표시. 오류가 있으면 INDD를 저장하고 해당 프레임 수정 후 다시 검사. 억지로 PDF를 통과시키지 않음.
6. 통과한 경우에만 PDF 출력 → 실제 파일 확인. Reload 후 예시 버튼을 다시 눌러 이벤트 정상 여부 확인.
실패하면 선택 디자인/폰트, 역할별 오류, 상세 진단, 문제 프레임 화면을 전달. 문서의 실제 줄바꿈/출력 일치 여부는 별도 실기 판정.
